Connectors

PeopleForce

HR data via an API key you create yourself. A few things behave differently from what you would expect, and they are worth reading before you rely on an answer.

Employees, departments, leave, recruitment and the HR knowledge base.

Connecting

  1. Click + Add Tool and pick PeopleForce MCP.
  2. In PeopleForce, go to Settings → Integrations → API and create a new API key.
  3. Paste it into the dashboard.
The key carries its creator’s permissions

A PeopleForce API key inherits the permissions of whoever created it. If an HR administrator creates the key, the connector can read everything that administrator can read — including salary and personal data. Create the key as an account whose access matches what you actually want the assistant to reach.

It can write, too

Most of this connector reads, but four actions change things: creating a leave request, adding a note to a candidate, moving an application to another stage, and disqualifying an application.

Disqualifying is not reversible by repeating it — asking twice disqualifies twice. Be specific when you ask for it.

Things that behave unexpectedly

Asking for “all employees”

There is no “everyone” option in the underlying API. A plain employee listing returns active employees only. A full headcount means asking for active and inactive separately. People who have left show as inactive.

Probation

Probation end dates are set by HR and reported as they stand — they are not calculated from a hire date, and in practice they range from a few months to well over a year and can be extended.

“Did this person pass probation?” is not answerable. The record carries no termination date, so someone who left during probation and someone who left five years later look identical: both are simply inactive.

Courses and training

There are no course, enrollment or completion records in the API. Training usually lives as free text in objectives and key results, which makes counting it unreliable. Some organizations model participation as a custom table on the employee profile — if yours does, that is readable, and Claude can list which tables exist before reading one.

Trends over time

Nothing in the API is timestamped or filterable by date, so historical trends cannot be reconstructed after the fact. If your organization needs them, a separate snapshot collector has to be running — ask whoever operates this deployment.

Try asking

  • “Who's out on leave next week?”
  • “List everyone in the Engineering department”
  • “Show me the skills on Jane Doe's profile”
