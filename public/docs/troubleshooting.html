Troubleshooting

Symptoms and their fixes. Most connector problems are one of two things: a credential that needs renewing, or a permission that did not exist when you connected.

The dashboard shows “Reconnect”

The stored credential can no longer be renewed. This is a Google-specific case — the other connectors use credentials that do not expire.

Fix: press Reconnect and approve again. Your settings, access rules and MCP URL all survive, so there is nothing to change in Claude.

A connector works, but one feature is refused

Almost always the same cause: that feature needs a permission that did not exist when you connected, and a credential only ever holds the permissions it was granted at the time.

The connection looks perfectly healthy, because from the provider’s point of view it is — it simply was not granted that one thing.

Fix: press Reconnect on the dashboard and approve again.

SymptomConnector
Deal lookups are refused, while contacts and companies workHubSpot
Company activity shows meetings and calls but empty emailsHubSpot
Attachments show as “file hidden” and downloads failSlack
Searching messages or files does not workSlack
Reactions are never captured by a channel subscriptionSlack

If it still fails after reconnecting, stop reconnecting — the permission is missing from the provider-side application or your organization’s policy, not from your consent. The error message distinguishes the two: it names both what was needed and what your credential actually holds.

Claude says “MCP Not Connected”

The connector was added to Claude before it was connected on the dashboard.

Fix: connect that service on the dashboard first, then retry in Claude.

Uploading an image to ClickUp fails

Claude is not permitted to fetch from the domain the image is served on.

Fix: in Claude, open Settings → Capabilities, scroll to Domain allowlist, and add clickup.awesome-mcp.xyz. This is a setting inside Claude — nothing on the dashboard can do it for you. See the images page.

A Slack bot connector sees nothing

A bot only has access to channels it has been invited to.

Fix: run /invite for the bot in each channel you want it to work in. If you want access to everything you can see without invitations, use the Slack MCP connector instead, which acts as you.

Slack search returns fewer results than expected

Results from channels your access rules exclude are removed after Slack has already paged them. A page can therefore come back empty while more matches exist further on. The response says how many results were hidden, so this is distinguishable from Slack finding nothing.

Fix: if the missing results are ones you should be seeing, widen the rules under Access Rules. Otherwise ask for the next page.

A pasted token stopped working

The key was revoked or rotated in the source service.

Fix: create a new key there, then use Re-enter token on the connection. This replaces the credential in place, so the URL you already gave Claude keeps working — do not delete the connection and start over.

The connector is using the wrong account

You approved with a different account than you meant to.

Fix: delete that connection and add the tool again, choosing the right account at the provider’s consent screen. You can also keep both — each connection gets its own row and its own URL, so you can give Claude whichever you want.

The MCP URL leaked

The URL contains your credentials.

Fix: delete the connection from the dashboard, which invalidates that URL immediately, then reconnect and give Claude the new one.

Still stuck

Check Updates — if a connector changed recently, the change is described there. It is also the fastest way to find out whether a permission was added and a reconnect is now expected.
