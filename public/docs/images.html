Getting started

Letting Claude post images

Moving an image into a document works across three connectors, and needs one setting in Claude that is easy to miss.

Three connectors can put an image somewhere: Google (into a Doc or a Slides deck), ClickUp (into a Doc page), and Slack (which is usually where the image comes from). They chain together, and the chain is the interesting part.

How the pieces fit

Most image workflows are the same shape: get a public URL for the image, then hand that URL to whatever is going to display it.

Slack downloadFile(format: "url")
      ↓  returns a public https://…/images/<hash>.webp URL
Google insertImageFromUrl    →  image lands in a Google Doc
ClickUp insertImageIntoPage  →  image lands in a ClickUp Doc page

You do not have to start in Slack — any publicly reachable image URL works as the input. Slack is just the common case, because a screenshot someone posted in a channel is not publicly reachable until it has been re-hosted.

ClickUp: the step everyone misses

Do this first, in Claude

Open Settings → Capabilities in Claude, scroll to Domain allowlist, and add:

clickup.awesome-mcp.xyz

Without it, asking Claude to upload an image to a ClickUp Doc fails — Claude is not allowed to fetch from the domain the image is served on. This is a setting in Claude, not on this platform, so there is nothing on the dashboard that can fix it for you.

Once the domain is allowed, ask for it in plain language: “Upload this image to the ‘Release notes’ page in ClickUp.”

ClickUp has no image-upload API for Docs, so the image is stored and served by this platform and embedded into the page as markdown. That is why the extra domain has to be allowed at all.

Google Docs and Slides

Google fetches the image itself, server-side, from whatever URL you give it. So a URL that is public works, and one that requires a login does not — which is exactly why a Slack file has to be re-hosted first.

Google Docs also accepts an image already in your Drive, or a file uploaded directly in the conversation, so you can say “insert this screenshot at the top of the doc” without any URL being involved.

Slack files

When Claude reads a Slack channel, attachments show up as lines like:

📎 screenshot.png — image/png, 284 KB — file ID: F09ABCDEF

Claude can then fetch that file two ways:

  • As a URL (the default) — the image is re-hosted and Claude gets back a public link, suitable for passing to Google or ClickUp.
  • Inline — the image itself comes back into the conversation so Claude can look at it. Use this when you want Claude to read the screenshot rather than move it.
Re-hosted Slack images are public

The generated link is unauthenticated. The address is long and unguessable, but anyone who has it can open the image — including an image from a private channel or DM. To bound that, Slack-sourced images are stored as short-lived and become eligible for deletion after a retention period (30 days by default). Treat the link as temporary: use it now, do not file it away.

If Slack files come back as “file hidden”, your Slack connection predates the file-reading permission. Press Reconnect on the dashboard — see troubleshooting.

Size limits

PathLimit
Image fetched from a URL20 MB
Image sent directly as data (ClickUp)about 1.5 MB — a few hundred KB is comfortable
Slack file returned inline into the conversation1.5 MB

Re-hosted images are converted to WebP, so the stored copy is usually a good deal smaller than what went in.

For whoever runs the server

Image hosting needs DATABASE_URL and IMAGE_PUBLIC_BASE_URL set on the deployment. Without them the image tools return a clear error rather than failing quietly. IMAGE_RETENTION_DAYS controls how long short-lived images survive (default 30; 0 disables expiry). These are deployment settings — there is nothing for an end user to configure here.
