REST API

A read-mostly HTTP surface alongside the connectors, for fetching bulk data without pushing all of it through the conversation.

Why it exists

Every answer a connector gives passes through the conversation, and every byte of it costs context. For bulk reads — a month of calendar events, a long channel history, a whole document body — that is wasteful: the assistant usually wants to filter or count, not read every row.

The REST plane lets Claude fetch those bytes with curl and process them with tools like jq, so only the answer comes back into the conversation. In practice you do not invoke this yourself — Claude reaches for it when a read is large.

Authentication

Two credentials work:

  1. A short-lived bearer. From any connected MCP session, Claude can mint a token that is valid for five minutes. This is the normal path.
  2. Your dashboard API key. Permanent, and accepted for compatibility with clients that cannot mint a token. Because it does not expire, treat it accordingly.
curl -H "Authorization: Bearer $TOKEN" \
  "https://app.awesome-mcp.xyz/api/v1/docs?q=pricing"
The permanent key can write

Most REST endpoints only read, but some accept POST and change data — creating a leave request, moving a recruitment application. Your dashboard API key is accepted on those too. Anyone holding that key can therefore make changes, not just look. You can rotate it from the dashboard.

JSON or text

RequestYou get
Default, or Accept: application/jsonThe upstream provider’s raw JSON, untransformed
Accept: text/plain, or ?format=textThe same readable rendering the connector would have produced

Examples

# Search your Google Docs
curl -H "Authorization: Bearer $TOKEN" \
  "https://app.awesome-mcp.xyz/api/v1/docs?q=onboarding"

# Read a doc as plain text rather than raw JSON
curl -H "Authorization: Bearer $TOKEN" \
  -H "Accept: text/plain" \
  "https://app.awesome-mcp.xyz/api/v1/docs/DOCUMENT_ID"

# Read a spreadsheet range and pull out one column
curl -sH "Authorization: Bearer $TOKEN" \
  "https://app.awesome-mcp.xyz/api/v1/sheets/SHEET_ID/ranges?range=A1:D50" \
  | jq '.values[][0]'

Full endpoint list

The complete catalog is machine-readable and always current:

  • /openapi.json — the OpenAPI specification for every endpoint
  • Per-service specifications are also published, for clients that want a smaller surface — for example /openapi-calendar.json

Not every connector has REST endpoints, and coverage differs by service. The specification is the authority on what exists.
