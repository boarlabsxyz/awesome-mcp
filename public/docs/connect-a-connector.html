Getting started

Connect a connector

How to get from a signed-out browser to a working MCP URL — and what each control on the dashboard actually does.

Sign in

Open the dashboard. If you are not signed in you will see a Sign in to continue dialog.

There are two ways in, and they reach the same account either way:

  • Google — one click, no password to choose. Signing in this way for the first time creates your account.
  • Email and password — use the sign-in page, or create an account there. Passwords must be at least 10 characters.

Either way, an API key is minted for you automatically the first time; you never have to create one.

This first sign-in asks for almost nothing: only your email address and basic profile. The permissions each connector actually needs are requested later, when you connect that connector — so you are never asked to approve access to a service you have not chosen yet.

Add a tool

  1. Click + Add Tool. (On an empty dashboard the button reads + Add Your First Tool.)
  2. Pick the service you want. The list is the same catalog you can browse on the integrations page.
  3. What happens next depends on the service — see the two flows below.
  4. You land back on the dashboard with a new row for the connection.
  5. Press Copy URL on that row.
  6. In Claude, add the URL as a custom connector (full instructions).
  7. Ask Claude to do something with it.

Two ways to connect

Every connector uses one of two flows. You do not choose — the dashboard picks based on what the service supports.

OAuth: you approve on the provider’s site

Picking one of these sends you straight to the provider’s consent screen. There is no form to fill in and no name to choose — the instance is named for you.

ConnectorYou approve at
Google Docs, Sheets, Slides, Drive, Gmail, CalendarGoogle
ClickUpClickUp
Slack (your own account)Slack
HubSpotHubSpot

Approve the request and you are redirected back to the dashboard. For Slack, the access-rules dialog opens automatically so you can decide which channels the connector may touch before you use it.

Paste a token: you create the credential yourself

These services have no OAuth app for us to send you to, so you create an API token in the service and paste it into the dashboard. The form shows you exactly where to click in that service.

ConnectorWhere to create the token
Slack BotCreate a Slack app, add bot scopes, install it to the workspace, copy the xoxb- token
Outline WikiPreferences → API and Access → New API Key
PeopleForceSettings → Integrations → API
HubSpot (fallback only)Settings → Integrations → Private Apps

Outline additionally asks for the URL of your wiki, since it is self-hosted — for example https://wiki.example.com, with no trailing slash.

HubSpot normally uses OAuth

The dashboard shows Connect with HubSpot, not a paste-token form. The private-app token path still exists as a fallback for deployments where the HubSpot OAuth app has not been configured. If you see a token form for HubSpot, that is why.

What the buttons on a connection do

ButtonWhat it doesWhen it appears
Copy URLCopies this connection’s MCP URL to your clipboard. The label flips to “Copied!” for a moment.Normally
ReconnectRe-runs the OAuth consent flow. Your settings and access rules are preserved. Needed when a token has expired, or when the connector has started requesting a permission you never approved.When the connection needs re-consent — it replaces Copy URL if the connection is broken, or sits next to it if it still works but needs new permissions

DeleteRemoves the connection. The MCP URL stops working immediately.Always

You can connect the same service more than once — two Google accounts, say. Each connection gets its own row and its own URL.

When a connector asks for new permissions

Tokens are frozen at the permissions they were minted with. When a connector gains a feature that needs a permission you did not originally grant, your existing connection keeps working for everything else and fails only on the new feature — and it will still look perfectly healthy on the dashboard.

The fix is always the same: press Reconnect and approve again. See Troubleshooting for the specific cases.
