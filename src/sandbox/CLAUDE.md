# Sandbox MCP — notes for Claude

A place for Claude to run code when the client has no shell: Python (Pyodide, CPython compiled to WebAssembly) or JavaScript, on this platform's own runner service, with per-user quotas and no outside vendor. A script reaches the user's connected services over the REST plane and returns only what it prints, which is the pattern that already works for shell clients (a 50 MB spreadsheet processed without crossing Claude's context). Verified locally on macOS arm64 through the real pool (`src/__tests__/sandbox/runner/deno.test.ts`, which CI's `sandbox` job runs on Linux x64). UNVERIFIED: the runner image build on Railway (`Dockerfile.sandbox-runner`), Railway private networking between the two services, and a real 50 MB spreadsheet. Check those first on a live deploy.

## Architecture

Two services. **Sandbox MCP** (`MCP_SLUG=sandbox`) checks the user, the lock and the quotas, mints the per-run bearer, and calls the **runner** (`src/sandbox/runner/`, its own Railway service) over HTTP with `SANDBOX_RUNNER_SECRET`. The runner keeps one session per user sandbox: a host directory mounted as `/home/user`, and a worker process (`worker.ts` under Deno, holding Pyodide) while it runs code or holds variables. `engine.ts` picks the runner client (`SANDBOX_RUNNER_URL`) or the pool in-process (`SANDBOX_RUNNER=local`, development only).

## Rules and limitations

- **Admins only** (`ADMIN_ONLY_MCPS`, `src/auth/admin.ts`), gated like the Admin MCP: hidden from non-admins in `/api/v1/catalogs`, `/connect/{slug}` answers 403, `resolveSession` refuses with 403 before any other path, and `requireAdminForEveryTool` re-checks the caller on every call (FastMCP authenticates once per session). To open it to everyone, remove the slug from the set and drop the guard from `server.ts`; `adminGuard.test.ts` checks the two agree.
- **Deno, never Node, runs user code.** Pyodide's `js` module and `run_js` give Python the whole host JavaScript runtime, so the process's permissions are the sandbox. Node 20's permission model has no network control: the spike reached arbitrary hosts from it. The worker is spawned (`workerCommand`, `pool.ts`) with an empty environment, `--allow-read` limited to Pyodide, the wheel directory and the session directory, `--allow-write` to the session directory, `--allow-net` to the allowlist, and no `--allow-env/run/ffi/sys`. **An empty allowlist omits `--allow-net` entirely; a bare flag would allow every host.** `deno.test.ts` checks each escape: environment, host files, `node:fs`, subprocesses, FFI, unlisted hosts (fetch and raw sockets), `permissions.request`.
- **The runner holds no secrets.** Deno's permissions are a software check on a shared kernel, not a VM. So the runner gets no `DATABASE_URL`, `REDIS_URL` or credentials, `main.ts` refuses to start if any are set, and the image runs as the unprivileged `node` user. That is why it is a separate service: the Sandbox MCP service needs the database and Redis.
- **Symlinks cannot be planted.** Deno refuses `symlink` under path-scoped permissions, and Pyodide treats the refusal as fatal, so the worker dies (`stopped: 'crashed'`, files kept). The host-side file tools still check `realpath` containment (`assertResolvesInside`), as the second line.
- **Memory is capped by `--wasm-max-mem-pages`** (`SANDBOX_MEMORY_MB`, default 1024). Python gets a clean `MemoryError` and the interpreter survives it. Importing every bundled package at once needs most of that 1024 MB, so do not lower the default without re-running `deno.test.ts`. The cap is **per WebAssembly memory**, and ArrayBuffers sit outside V8's 512 MB heap, so JavaScript could allocate past it. The watchdog therefore also bounds the whole process's RSS (`SANDBOX_MAX_RSS_MB`, default `SANDBOX_MEMORY_MB` + 1024; `stopped: 'memory'`).
- **The watchdog measures every live worker from outside the process, for its whole life** (`SandboxPool.watch`, once a second):
  - disk, always;
  - RSS, always;
  - CPU between runs, where more than half a core means code left running and the worker is stopped.
  A run can return with work still going (a `setInterval`, an asyncio task), or forge its own end: user code shares the worker's stdout, so a `done` line can be faked. Hardening inside the worker (captured `JSON`/`writeSync`, random run ids) only raises the bar. These measurements are what bound such code, and the next run says why its interpreter was replaced (`previousStop`). CPU and RSS come from `/proc`, so on macOS only disk is watched.
- **Every protocol line is untrusted.** Non-objects are ignored, every cap is applied on the host side as well — output, results, images (3, 1.5 MB each), error fields (20,000 characters) — since forged messages never passed the worker's, and a line over 16 MB kills the worker. On SIGTERM the pool stops admitting sessions before it closes them, so a redeploy leaves no directory or worker behind.
- **One run at a time per worker; a timeout kills the process.** There is no softer stop: a JavaScript loop cannot be interrupted, and a Python one only from inside the process. Files survive, because they live on the host, but variables are gone. The next run reports `restarted: true`, which becomes a note.
- **At most `SANDBOX_MAX_WORKERS` live workers (default 4).** When the pool is full, the least recently used idle worker is stopped to make room (its user's next run is told). With every worker busy, the run is refused.
- **Disk:** `SANDBOX_MAX_DISK_MB` (500) and `SANDBOX_MAX_FILES` (10,000) per session.
  - The watchdog measures a session every second, and measures again before a run reports success, so a run shorter than one interval cannot slip past.
  - `writeFile` refuses a write whose projected usage is over the limits: an overwrite replaces the old bytes, and missing parent directories count as entries.
  - The scan stops as soon as the entry count passes the limit. It makes `chmod 000` directories readable again, so code cannot hide bytes from it, and removal does the same, so an unremovable directory cannot fail idle cleanup. An idle cleanup that still fails is logged, never an unhandled rejection that ends the runner.
- **Races with the idle timer:** a worker that finishes starting after its session ended is killed, and a write that raced the end is refused, with the recreated directory removed.
- **Packages:** the wheels in `runner/packages.ts` are baked into the image (`prefetch.ts`) and loaded on import (`loadPackagesFromImports`). The wheel directory is read-only to workers. A shared writable one would let one user plant a wheel another user loads. So a Pyodide package not in the list cannot be loaded, and the network allowlist has no CDN. Pure-Python packages install from PyPI with micropip. Keep the `runCode` description's list in step with `packages.ts`.
- **One sandbox per user, answered from the caller.** `resolveSession` treats `sandbox` like `storage` (`PER_USER_MCPS` in `src/mcpAuthenticate.ts`): no connection or credential is consulted, the instance id is kept only when it is the caller's own Sandbox connector, and a sandbox instance id replayed against another server answers 400. One connector per user is enforced by the partial unique index `idx_mcp_connections_one_sandbox`.
- **The user → sandbox mapping, the run lock and the quotas live in Redis** (`state.ts`), so every Sandbox MCP replica sees the same sandbox and spend. **The runner is ONE replica** (`numReplicas: 1`): its sessions are in memory. A runner restart ends every session, and the next call reports `sandbox: "replaced"`. The runner's idle timer (`SANDBOX_IDLE_MINUTES`, default 10) stops a session and deletes its directory. **Only `runCode` extends it; file calls never do**, so unmetered calls cannot keep a sandbox, or code a run left behind, alive.
- **Every call that touches the sandbox takes the per-user lock; a second call is refused, not queued.** A queue would strand the caller's socket behind a 5-minute run. The lock also serializes creation. Its TTL (run timeout + 90 s, covering the interpreter's start) frees a lock whose holder died. **Right before the run the lease is renewed by compare-and-set** (`SandboxLease.renew`, a Lua script): a call whose lease ran out while creating the sandbox refuses instead of running alongside the next holder.
- **The REST bearer is minted per run and revoked when the run ends, success or failure.** It goes in the run's `envs` (`os.environ` in Python, removed again after the run; a closure behind `api()` in JavaScript), never at creation, so an idle sandbox holds no working credential. Its TTL is the run's timeout + 60 s for a cold interpreter start + 30 s. **If revoking fails after 3 tries, the sandbox is killed instead**, since it is the only place the token was handed; if the kill fails too, the response gives the token's expiry. Killing the sandbox does not reach a copy the run already sent elsewhere (to Storage, say): such a copy works until the token expires, which is why the TTL stays short. The bearer reaches every `/api/v1/*` service the user has connected (it is not service-scoped). That is the point, and the `runCode` description says so.
- **`api()` in Python is synchronous via `run_sync`** (JSPI, on in Deno 2.9's V8) over `pyfetch`; `api_async` is there for async code. `urllib` cannot open sockets in Pyodide; `requests` works (urllib3's Emscripten backend).
- **Egress allowlist:** the host of `BASE_URL` (with its port when it names one, as `localhost:8080` does), `pypi.org` and `files.pythonhosted.org`.
- **Quotas fail closed.** `SANDBOX_MAX_RUNS_PER_DAY` (200) and `SANDBOX_MAX_SECONDS_PER_DAY` (3600) are counted per UTC day; with Redis unreachable a run is refused with a reason. **A run's seconds are reserved before it starts** (`reserveRun`: the timeout, cut to what is left today, and the response says when it was cut) and settled afterwards (`settleSeconds`), so a Redis failure after the run over-charges rather than losing the time. Only taking the lock and reserving fail closed; a runner error inside the run passes through as itself. The runner's own refusals (`SandboxRefusal`: capacity, disk, a path outside `/home/user`) reach the caller as worded.
- **Output is capped and says so.** The worker forwards at most 20,000 characters each of stdout and stderr, and counts the rest (`truncated` gives the totals; a lower bound when the run was killed before reporting them). Text results share one 20,000-character budget, cut in the worker before sending (`resultsTotal`). Up to 3 PNGs of at most 1.5 MB come back: matplotlib figures left open at the end of a Python run, rendered with Agg. Tracebacks are trimmed to the user's own frames (`<code>`) and capped at 5,000 characters. A timeout returns what was printed up to that point, with `timedOut`.
- **The file tools see only `/home/user`** (`toHostPath`); Python's other paths are in-memory and invisible to them. The worker's working directory is the session directory, so JavaScript's relative paths (`Deno.writeTextFile('out.csv')`) land in `/home/user` too. JavaScript cannot use the literal `/home/user` path: that exists only inside Pyodide. They work on the host directory without a worker. `readFile` reads only `maxChars × 4` bytes (1.5 MB for an image). `listFiles` shows at most 500 entries, with the total. `listFiles`/`readFile` never create a sandbox; `writeFile` and `runCode` do.
- **Argument names (`code`, `path`, `content`, `language`) stay out of `PREVIEW_KEYS`**, so code and data never reach `tool_call_events`.
- **No REST siblings, on purpose:** running code from curl gains nothing over a local shell. The server registers `listRestEndpoints` (scripts are written against those routes) but not `mintRestBearerForCurl`, because each run carries its own bearer.
- **No shell, and no native packages beyond the bundle.** That is the trade against a VM sandbox.
- **Not wired in the combined web+MCP mode** (`MCP_MODE=all`), like Storage and every connector after the original nine.
- **Deferred:** script backfills for Storage migrations; interrupting Python without killing the worker (Pyodide's interrupt buffer needs the run in a Web Worker).

## Deployment

- **Runner** — a Railway service named `sandbox-runner`. Set its config file path to `railway.sandbox-runner.json`, which builds `Dockerfile.sandbox-runner` (Debian, because Deno ships only glibc builds; the main image is Alpine). Give it **no public domain** and only `SANDBOX_RUNNER_SECRET` (at least 32 characters), plus optionally `SANDBOX_MEMORY_MB`, `SANDBOX_MAX_WORKERS`, `SANDBOX_MAX_DISK_MB` and `SANDBOX_MAX_FILES`. Size its memory for `SANDBOX_MAX_WORKERS × (SANDBOX_MEMORY_MB + ~600 MB)`. It listens on `::` for the private network.
- **Sandbox MCP** — `TRANSPORT=httpStream`, `MCP_MODE=mcp`, `MCP_SLUG=sandbox`, `DATABASE_URL`, `REDIS_URL` (the same Redis as the web service, which is where minted bearers are checked), `BASE_URL`, `SANDBOX_RUNNER_URL=http://sandbox-runner.railway.internal:8080`, the same `SANDBOX_RUNNER_SECRET`, and optionally the `SANDBOX_*` quota limits.
- **Web service** — set `SANDBOX_MCP_URL`. It counts as ready from that alone (`sandboxConfigured`). Without a database, or without the URL or a runner, `/connect/sandbox` answers 503; on the Sandbox service every tool says the runner is missing.
- **Local development** — `npm i -g deno@2.9.6` (or set `SANDBOX_DENO_PATH`), `npm run sandbox:prefetch` once, then `SANDBOX_RUNNER=local` on the Sandbox MCP process. Or run `npm run sandbox:runner` beside it with a secret and point `SANDBOX_RUNNER_URL` at it.

## Source Files

| File | Contains |
|------|----------|
| `src/sandbox/server.ts` | Tool registrations; images go back as MCP image content |
| `src/sandbox/ops.ts` | Tool bodies: acquiring the sandbox, the per-run bearer, output caps, notes |
| `src/sandbox/provider.ts` | `SandboxProvider`, `SandboxRefusal`, `SandboxNotFound` (no imports; both sides share it) |
| `src/sandbox/engine.ts` | Which engine: the runner client, the local pool, or none |
| `src/sandbox/state.ts` | Redis: user → sandbox id, the run lock, daily quotas, `sandboxLimits()` |

| `src/sandbox/connect.ts` | One-click connect (`src/util/firstPartyConnect.ts`, shared with Storage) |
| `src/sandbox/runner/pool.ts` | `SandboxPool`: sessions, directories, worker start/eviction, disk watchdog, file tools, `workerCommand` (the Deno permissions) |
| `src/sandbox/runner/workerProcess.ts` | One worker process: spawn, the JSON-lines protocol, timeout kill |
| `src/sandbox/runner/worker.ts` | Runs under Deno: Pyodide, the `awesome` helper, output capture, figures |
| `src/sandbox/runner/server.ts` / `client.ts` | The runner's HTTP API and the Sandbox MCP's client for it |
| `src/sandbox/runner/main.ts` | Runner entry point; refuses to start holding credentials |
| `src/sandbox/runner/packages.ts` / `prefetch.ts` | The bundled wheels, and baking them in |
