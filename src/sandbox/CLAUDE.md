# Sandbox MCP — notes for Claude

A place for Claude to run code when the client has no shell: Python, JavaScript or bash in a hosted E2B sandbox, on this platform's `E2B_API_KEY` with per-user quotas. A script reaches the user's connected services over the REST plane and returns only what it prints, which is the pattern that already works for shell clients (a 50 MB spreadsheet processed without crossing Claude's context). UNVERIFIED live: no run has gone through a real E2B account or a deployed client yet. Check the egress allowlist first (see below), then that per-run `envs` reach the Python and JavaScript kernels, then that a timed-out run is stopped by the kernel restart.

## Rules and limitations

- **Admins only** (`ADMIN_ONLY_MCPS`, `src/auth/admin.ts`), gated like the Admin MCP: hidden from non-admins in `/api/v1/catalogs`, `/connect/{slug}` answers 403, `resolveSession` refuses with 403 before any other path, and `requireAdminForEveryTool` re-checks the caller on every call (FastMCP authenticates once per session). To open it to everyone, remove the slug from the set and drop the guard from `server.ts`; `adminGuard.test.ts` checks the two agree.
- **One sandbox per user, answered from the caller.** `resolveSession` treats `sandbox` like `storage` (`PER_USER_MCPS` in `src/mcpAuthenticate.ts`): no connection or credential is consulted, the instance id is kept only when it is the caller's own Sandbox connector, and a sandbox instance id replayed against another server answers 400. One connector per user is enforced by the partial unique index `idx_mcp_connections_one_sandbox`.
- **The user → sandbox mapping, the run lock and the quotas live in Redis** (`state.ts`), so every replica sees the same sandbox and spend. The vendor's own timeout (`SANDBOX_IDLE_MINUTES`, default 10) is what kills an idle sandbox, so nothing leaks if our process dies. **Only `runCode` extends it; file calls never do.** E2B bills a live sandbox by the second whatever it is doing, and code a run left behind (a background thread) keeps working while it lives, so unmetered calls must not keep it alive: a user's sandbox time is bounded by their metered runs plus one idle window after each. A mapping whose sandbox is gone means a new one is created, and the response says `sandbox: "replaced"` with a note that files and variables are gone. That is never silent.
- **Every call that touches the sandbox takes the per-user lock; a second call is refused, not queued.** A queue would strand the caller's socket behind a 5-minute run. The lock also serializes creation, so two overlapping calls cannot start two sandboxes. Its TTL (run timeout + 60 s) frees a lock whose holder died. **Right before the run the lease is renewed by compare-and-set** (`SandboxLease.renew`, a Lua script): a call whose lease ran out while it was creating the sandbox refuses instead of running alongside the next holder.
- **The REST bearer is minted per run and revoked when the run ends, success or failure.** It is passed as `AWESOME_API_TOKEN` / `AWESOME_API_BASE` in the run's `envs`, never at sandbox creation, so an idle sandbox holds no working credential (a script that saved the token in a variable holds a dead one). Its TTL is the run's timeout + 30 s, so a call dispatched near the end of a long run is not refused. **If revoking fails after 3 tries, the sandbox is killed instead** — it is the only place the token was handed — and the response says so; if the kill fails too, it gives the token's expiry. The bearer reaches every `/api/v1/*` service the user has connected, since it is not service-scoped. That is the point, and the `runCode` description says so.
- **The run timeout is capped at 300 s** (`SANDBOX_MAX_TIMEOUT_SEC`, never above 300), which also bounds the lock and the bearer's life. The SDK's `requestTimeoutMs` is set to the run timeout plus a margin, or a long run would fail at its 30 s request default.
- **A timed-out run is stopped, not just abandoned.** A request timeout does not prove the code stopped, so the language's kernel is restarted (`interrupt`: variables go, files stay); when no kernel for the language is found, the sandbox is killed. Either way the response says which. UNVERIFIED: the context language names E2B reports are assumed to match ours (plus `js`).
- **Egress is an allowlist:** the host of `BASE_URL`, `pypi.org`, `files.pythonhosted.org` and `registry.npmjs.org`, with everything else denied. UNVERIFIED: third-party pages say E2B's lower usage tiers restrict internet access, so confirm on the real account that the allowlist (and `pip install`) works.
- **Quotas fail closed.** `SANDBOX_MAX_RUNS_PER_DAY` (200) and `SANDBOX_MAX_SECONDS_PER_DAY` (3600) are counted per UTC day. With Redis unreachable, a run is refused with a reason: the opposite of `loginRateLimit.ts`, because an open counter spends our money. **A run's seconds are reserved before it starts** (`reserveRun`: the timeout, cut to what is left today, and the response says when it was cut) and settled to the time used afterwards (`settleSeconds`), so a Redis failure after the run over-charges rather than losing the time. Only taking the lock and reserving fail closed: a vendor error inside the run passes through as itself.
- **Output is capped and says so:** 20,000 characters each for stdout, stderr and the text results together (`truncated` gives the totals), up to 3 images of at most 1.5 MB, and tracebacks at 5,000 characters. A timeout returns what was printed up to that point, with `timedOut`.
- **`readFile` downloads only what it can show** — `maxChars × 4` bytes (a UTF-8 character's maximum), or 1.5 MB for an image — reading the size first and a stream prefix past it; the response gives the file's size.
- **`listFiles`/`readFile` never create a sandbox** (they answer "No sandbox is running"). `writeFile` and `runCode` do.
- **Argument names (`code`, `path`, `content`, `language`) stay out of `PREVIEW_KEYS`**, so code and data never reach `tool_call_events`.
- **No REST siblings, on purpose:** running code from curl gains nothing over a local shell. The server registers `listRestEndpoints` (scripts are written against those routes) but not `mintRestBearerForCurl`, because each run carries its own bearer.
- **Node 20 pin.** `@e2b/code-interpreter` is pinned to 2.8.3 and `e2b` to 2.55.0 (a `package.json` override): later versions require Node ≥ 22.19, and the image runs Node 20. Lift both when the Dockerfile moves to Node 22.
- **Not wired in the combined web+MCP mode** (`MCP_MODE=all`), like Storage and every connector after the original nine; it runs as its own `MCP_MODE=mcp` service.
- **Deferred:** a JavaScript helper (the Python one is `/home/user/awesome.py`, written at creation), a global cap on concurrent sandboxes, and script backfills for Storage migrations.

## Deployment

A Railway service like the other connectors: `TRANSPORT=httpStream`, `MCP_MODE=mcp`, `MCP_SLUG=sandbox`, `DATABASE_URL`, `REDIS_URL` (the same Redis as the web service, which is where minted bearers are checked), `BASE_URL`, `E2B_API_KEY`, and optionally the `SANDBOX_*` limits. Set `SANDBOX_MCP_URL` on the web service: it counts as ready there without a key of its own (`sandboxConfigured`). Without a database, or without both the URL and a key, `/connect/sandbox` answers 503; on the Sandbox service every tool says which of key or database is missing.

## Source Files

| File | Contains |
|------|----------|
| `src/sandbox/server.ts` | Tool registrations; images go back as MCP image content |
| `src/sandbox/ops.ts` | Tool bodies: acquiring the sandbox, the per-run bearer, output caps |

| `src/sandbox/schemas.ts` | Tool parameter schemas |
| `src/sandbox/connect.ts` | One-click connect (`src/util/firstPartyConnect.ts`, shared with Storage) |
