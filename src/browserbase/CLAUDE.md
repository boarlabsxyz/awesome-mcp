# Browserbase — notes for Claude

## Known Limitations

- **Browserbase is a PROXY to someone else's MCP server, and the `sessionId` contract is the whole design:** the six browser tools (`start`/`end`/`navigate`/`act`/`observe`/`extract`) forward to the hosted server at `https://mcp.browserbase.com/mcp` rather than reimplementing Stagehand — which is also why this connector needs **no model key**: Gemini runs on Browserbase's side and they pay for it. Auth is `Authorization: Bearer <key>` (`x-bb-api-key` also works; the `browserbaseApiKey` **query param is a deprecated fallback**), so the key never has to appear in a URL the user could copy. **A fresh MCP transport is opened per tool call and the `Mcp-Session-Id` is deliberately never cached**, so the caller must thread the Browserbase `sessionId` through every call. That is not a shortcut: Browserbase's own docs name this exact client shape — "Some MCP clients open a new transport on every tool call … which means the server has no active session to fall back to and calls fail with `No active session`" — and prescribe passing the id every time, noting "an explicit `sessionId` always takes priority over the transport's current session" and that a stale id **errors rather than silently redirecting**. Caching a transport would be actively worse here, because this server runs multiple replicas and a cached id a sibling replica does not hold is precisely that failure. The cost is three round-trips on an operation that already takes seconds in a real browser; the payoff is that any replica can serve any call. `No active session` is rewritten into an instruction naming `start`, because the raw string says nothing about what to do. **Hosted-only means the CLI flags do not exist**: `--contextId`, `--persist`, `--proxies`, `--verified`, `--browserWidth/Height` and `--experimental` work only in the self-hosted server, so do not add parameters for them. **A session bills until it is released or hits the project timeout**, which is why `listBrowserSessions`/`getBrowserSession`/`forceEndBrowserSession` exist over REST and are not garnish — without them a session whose id outlived its conversation is **invisible through this server while still costing money**, and `end` falls back to REST `REQUEST_RELEASE` precisely because reporting a close that did not happen leaves a browser billing. The real backstop is the project's `defaultTimeout` in Browserbase settings (an ops step, not code); creating sessions ourselves via `POST /v1/sessions` with a bounded `timeout` would give a per-call cap but **it is unverified** whether hosted `start({sessionId})` adopts a REST-created session nothing has connected to over CDP — do not ship a `timeoutSeconds` parameter until that is tested, since one that silently does nothing is worse than none. **Domain rules bind `navigate` only** (`providerTokens.accessRules`, dashboard → Domain Rules): it is the one tool that declares a destination, so `act` can click through to anywhere and `start` can reattach to a session already navigated off-list — it is a guardrail against an agent wandering, **not a security boundary**, and the `act` description says so rather than letting a model infer containment. Absent rules mean **unrestricted** (the opposite of Slack's fail-closed `getRules`) and are deliberately **never written back as empty defaults**: an empty object is a non-empty value that would survive every reconnect merge and reset the user's rules — the trap `PRESERVED_ON_RECONNECT` documents. Matching is **label-boundary hostname suffix, never glob**: `example.com` covers `app.example.com` but not `notexample.com`, because glob semantics on a hostname are ambiguous in the widening direction. Note the paste-token re-auth path (`persistPasteConnectionFor`) now preserves `accessRules` for the same reason the OAuth path does — it used to replace `providerTokens` wholesale, which would have silently widened access on every reconnect. Finally, **`BROWSERBASE_API_KEY` and `BROWSERBASE_PROJECT_ID` are already taken** by the unrelated e2e cloud-browser transport in `.github/workflows/e2e-smoke.yml`; this connector reads neither (the key is per-connection) and the only env var it owns is `BROWSERBASE_MCP_URL` and `BROWSERBASE_ENABLED`. **The connector is seeded but HIDDEN by default (`BROWSERBASE_ENABLED`)**, exactly as `peopleforce-v4` is: the row is written on every boot with `isActive: false`, both catalog backends filter on it, so it drops out of `/api/v1/catalogs` and therefore out of the dashboard's Add Tool list and the public integrations page. `BROWSERBASE_ENABLED=true` restores it — a **restart, not a deploy**, since the seed upserts — and the comparison is strict `=== 'true'`, so `yes`/`TRUE` leave it hidden (verified). It is seeded rather than skipped so the flag can flip both ways without orphaning an existing connection, but be clear on what hiding costs one: `getMcpCatalog` filters on `isActive` too, so the entry reads as **missing**, `renderInstanceRow` degrades to the raw slug and a fallback icon, and `getMcpUrl` returns `''` so Copy URL silently yields nothing. The connection keeps working — `mcp:browserbase` stays in `scopeMap.ts` either way — it is only the dashboard affordances that degrade. On the REST plane, **`act` is deliberately absent**: it submits forms on third-party systems, that plane accepts the permanent dashboard API key, and a curl has no confirmation affordance.
- **Nothing the hosted Browserbase server returns is forwarded verbatim, and that rule was learned the hard way (live run, 2026-10-08):** `navigate` answers with a serialized Page/CDP object — ~15 KB carrying the internal connect websocket URL, its `signingKey` JWT repeated several times, internal `*.svc.cluster.local` hostnames and a flow-logger session id — and the first version handed all of it to the model, the transcript and, over REST, any API-key holder. So `navigate` is now projected to an **allowlist** (`url`, `status`, `title`) rather than redacted: the payload's shape is Browserbase's to change, and redaction can only remove secrets someone already thought of. The URL is echoed from what was **requested**, never read back out of the payload. Redaction (`src/browserbase/responseSafety.ts`) is the backstop for `extract`/`observe`, whose payload *is* the point and therefore cannot be allowlisted. Separately, `extract` with an instruction can make the extraction model emit thousands of newlines until its JSON is cut off, and the upstream `AI_NoObjectGeneratedError` echoed **~214 KB** of raw text — enough to overflow a 25 K-token client on its own, so the error that most needed reading was the one that could not be read. Error text is capped at 1 KB, and degenerate character runs are **collapsed before** truncating: truncating 214 K newlines at 4 KB still yields 4 KB of nothing and hides whatever real content followed. There is **no hosted parameter to cap the upstream model's output** (`modelName`/`modelApiKey` are the only model knobs), so detection-and-collapse is the only half available here. Sanitising runs at **both** the proxy and the op layer on purpose — one choke point is one new call site away from being bypassed, which is exactly how this shipped. The `{"success":true,"data":…}` envelope is unwrapped so every tool renders the same way, instead of act/observe/extract handing back a raw wrapper while start/end/getBrowserSession returned text.

## Source Files

| File | Contains |
|------|----------|
| `src/browserbase/server.ts` | Browserbase tool definitions (9 tools: the 6 hosted browser tools proxied through `responseSafety`, plus the three REST session-cost tools) |
| `src/browserbase/mcpProxyClient.ts` | Hand-rolled MCP Streamable-HTTP client for `https://mcp.browserbase.com/mcp` — SSE-frame reader, per-call transport, `No active session` rewrite. Ported from `e2e/transports/mcpHttp.ts` |
| `src/browserbase/apiHelpers.ts` | `BrowserbaseClient` — `x-bb-api-key` client for the Browserbase REST API (sessions, projects, usage); sets `.status` on errors so `sendUpstreamError` reads it natively |
| `src/browserbase/responseSafety.ts` | Everything that happens to upstream text before it is returned: the `navigate` allowlist projection, credential/topology redaction, degenerate-run collapse, and the payload/error size caps. Shared by both surfaces |
| `src/browserbase/accessRules.ts` | Domain allow/block rules: `assertDomainAllowed` (pure), `BrowserbaseAccessDenied`, `validateDomainPattern` — label-boundary hostname matching, shared by the tool and the dashboard route |
| `src/browserbase/ops.ts` / `restOps.ts` | One `op*` per MCP tool (returns rendered strings) and one `perform*` per REST route (returns data); schemas composed from the field objects in `schemas.ts` so the two surfaces cannot drift |
